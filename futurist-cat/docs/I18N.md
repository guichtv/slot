# I18N - CYBER CAT

> **Traductions non relues par un locuteur natif.** Les 14 langues ajoutées (de, es, pt, fi, pl, ru, tr, id, vi, ja, ko, zh, hi, ar) sont des traductions produites par IA. Aucun locuteur natif ne les a relues. Seuls `en.json` (référence) et `fr.json` sont des textes d'auteur. Avant la soumission à Stake, il faut au minimum faire relire les règles (`rules.*`), la phrase `rules.malfunction` et les variantes `@social` par un natif, et regarder chaque langue à l'écran.

## Fonctionnement

- Un fichier par langue : `src/i18n/locales/<code>.json`, clé plate → chaîne. Chaque fichier a **toutes les clés de `en.json`, dans le même ordre**, indentation 2 espaces, UTF-8.
- Résolution dans `I18n.t()` : `clé@social` (si mode social) → `clé` dans la langue → `clé` en anglais → la clé brute.
- Les `{placeholders}` sont remplacés par le code. Ils gardent exactement le même nom et le même nombre que l'anglais (le test le vérifie).
- `ar` : `document.documentElement.dir = "rtl"` est posé par le code ; les chaînes arabes n'ont pas de marques de direction. Les noms produit latins (WILD, SCATTER, ANTE…) restent en latin dans le texte arabe.

### Variantes sociales (`clé@social`)

En mode social (Stake social casino), `t('x')` renvoie `x@social` s'il existe, sinon `x`. Une variante `@social` n'existe que là où le texte de base contient du vocabulaire de jeu d'argent. Les 22 clés concernées sont : `hud.bet`, `hud.buy`, `hud.buy.aria`, `hud.betUp`, `hud.betDown`, `buy.title`, `buy.confirm.bet`, `buy.confirm.ok`, `rules.ways`, `rules.paytable`, `rules.feature.scan`, `rules.feature.doubleScan`, `rules.feature.bonus`, `rules.feature.super`, `rules.ante`, `rules.maxWin`, `rules.malfunction`, `hist.bet`, `replay.bet`, `err.ERR_GLE`, `rules.tiers`, `err.session`.

Règle d'écriture d'une variante sociale : aucun mot de pari, de mise, d'achat, de paiement, de gain en argent, d'argent, de liquide ni de casino dans la langue. On suit l'anglais : « play » / « play amount » (FR « jeu » / « montant de jeu »), « cost » au lieu de « price », « wins » au lieu de « pays », « get bonus » au lieu de « buy bonus ». Termes retenus pour « play amount » : de *Spielbetrag*, es *monto de juego*, pt *valor da jogada*, fi *pelimäärä*, pl *wartość gry*, ru *сумма игры*, tr *oyun miktarı*, id *jumlah main*, vi *mức chơi*, ja *プレイ額*, ko *플레이 값*, zh *游玩数额*, hi *खेल राशि*, ar *مقدار اللعب*.

**Trous comblés** : `rules.tiers` (« … the **bet** ») et `err.session` (« … the **casino** ») s'affichaient aussi en social ; ils ont maintenant leur variante `@social` dans les 16 langues (« play amount » / « platform »). Autre point : `hud.net` est traduit par une notion de solde gains/pertes dans certaines langues (vi *LÃI/LỖ*, ja *収支*, ko *손익*). Ces chaînes s'affichent en social si la juridiction montre le net de session.

## Termes gardés tels quels

`CYBER CAT`, `SPIN` (clé `spin`), `WILD`, `SCATTER` (y compris dans les phrases : « 3 SCATTER », « Scatter ×{x} »), `ANTE`, `SCAN`, `DOUBLE SCAN`, `RTP`, `FS` (« +{n} FS »), `ways` dans « 1024 ways ». `BUY BONUS` (`hud.buy`, `buy.title`) reste en anglais dans **toutes** les langues, comme en français (D22), même en écriture non latine ; ses variantes sociales sont traduites.

**Contraintes techniques** : `fs.add` (`+{n} FS`) et `win.base` (`{base}`) sont dessinés avec la police bitmap `CC-Num` (`src/render/texts.ts`), qui ne contient que l'ASCII et quelques lettres latines. Ils doivent rester **identiques à l'anglais** dans toutes les langues. Les noms de paliers (`tier.*`) passent par un `Text` Pixi avec toutes les polices locales et peuvent être traduits.

## Choix par langue à connaître

- **Tutoiement / vouvoiement** : on évite le pronom quand c'est possible (de : infinitif, « Zum Spielen irgendwo klicken »). Sinon : es tutoiement (usage latino-américain), pt « você », pl tutoiement, ru/tr/id/vi/hi/ar forme polie.
- **Solde** : jamais « crédits ». de *SALDO* (plutôt que *Guthaben*, qui peut se relire « crédit »), es/pt/fi/pl/id *SALDO*, ru *БАЛАНС*, tr *BAKİYE*, vi *SỐ DƯ*, ja 残高, ko 잔액, zh 余额, hi बैलेंस, ar الرصيد.
- **pt** : *rodada* = spin, *partida* = manche (`hist.round`, erreurs), pour ne pas confondre les deux.
- **fi** : *kierros* = spin / tour, *pelikierros* = manche ; en social, *maksaa* (qui veut dire à la fois « coûter » et « payer ») est évité.
- **pl / ru, pluriels** : les nombres de spins de bonus (`intro.spins`, `buy.spins`, `rules.nineLives`, `rules.doubleGaze`) prennent le génitif pluriel, juste pour n ≥ 5 (config actuelle : 9). Si un bonus passe à 2, 3 ou 4 spins, ces chaînes deviennent fautives. `rules.kind` (`{n} z rzędu`, `{n} подряд`) et `rules.retrigger` (`SCATTER ×{s} … +{n}`) sont écrits pour être justes quel que soit n (retrigger actuel : 3 → 3 FS, 4 → 5 FS).
- **tr** : RTP écrit `%{rtp}` (ordre turc) ; confirmation sociale `BAŞLAT` (« lancer »), parce que *AL* seul se lit « acheter ».
- **ja / zh / ko / hi / ar** : « un / deux points laser » en toutes lettres (一つ / 二つ, 一个 / 两个, 하나 / 두 개…), sans ajouter de chiffre absent de l'anglais.
- **ja** : on évite お試し et 試玩 (qui évoquent le mode démo) : « Retry » = 再試行, « réessayer plus tard » = やり直してください.
- **zh** : `err.session` dit 娱乐场 plutôt que 赌场 (« tripot »), parce que cette chaîne s'affiche aussi en social.
- **ar** : dans la règle du laser, les flèches sont en `←`, dans le sens de lecture RTL ; confirmation sociale `تفعيل` (« activer »).

## Mots interdits (revue Stake)

Dans **toutes** les chaînes de **toutes** les langues : demo (et ses traductions), test (et ses traductions), fun (le mot), credit(s) (et ses traductions), provisional, placeholder, lorem. Le test `tests/i18n.test.ts` les cherche.

Motifs : les mots en écriture latine ont des bornes Unicode (`(?<![\p{L}\p{N}])…(?![\p{L}\p{N}])`, car `\b` ne connaît que l'ASCII en JavaScript) ; les formes cyrilliques, CJK, devanagari et arabes (`демо`, `デモ`, `演示`, `кредит`, `积分`, `تجريبي`…) sont cherchées telles quelles. Le test vérifie aussi que ces motifs attrapent bien ces formes. Les mêmes motifs servent à la porte de release (`node tools/check-release.mjs --locales`, lancé aussi par `--pre`).

## Modifier ou ajouter une chaîne

1. Ajouter la clé dans `en.json` (référence), puis dans `fr.json` et les 14 autres fichiers, **au même endroit**.
2. Si le texte parle de mise, d'achat, de paiement ou de casino, ajouter `clé@social` dans les 16 fichiers.
3. Lancer `npx vitest run tests/i18n.test.ts` : clés, placeholders, mots interdits, présence de `rules.malfunction`.
4. Faire relire la nouvelle chaîne par un natif, ou la noter comme non relue.
